# 商用发布验收与尚未解决的边界

本次代码交付是架构基础重构，不能等同商用认证。以下门槛必须在目标构建机、云机与浏览器完成。

## 已实现的基础能力

- 会话统一持有全部 peer，按路故障隔离、整体关闭与新加入时的准入限额。
- 独立恢复秘密、同页面保留媒体、新页面重建 peer、过期回收和旧回调代次校验。
- 控制权交接时串行释放旧输入；回包跟随控制者。
- 控制者优先/最小预算策略、弱网档位、时间平滑、编码目标上限和关键帧请求合并。
- 视频/PCM 的 Java payload 共享，避免逐观看者重复分配；新视频订阅等待参数集与 IDR。
- 显式生产/调试接入、唯一房间授权、可配置 native 媒体端口、正确的 ICE 字段改写。
- 删除外部 Opus 透传队列、旧单用户 admission 和重复 WebRTC packet sink。
- 恢复 native 源码/库哈希打包门禁；JNI 编译服务器交付配套库和清单，APK 服务仅导入和校验。

## 发布阻断项

| 门槛 | 必须提供的证据 |
|---|---|
| 构建一致性 | 固定 libwebrtc revision、补丁、编译参数、工具链和 native-build.json；完整 JNI/APK/H5 构建 |
| Android 校验 | Gradle test/lint/checkstyle；平台签名、投影/录音/输入权限；支持 Android/SoC 列表 |
| H.264 正确性 | 部署版本内部所有丢帧路径与源帧逐帧关联，接收解码参考链无长期断裂 |
| 协商正确性 | SDP profile/level 与真实 SPS、分辨率、帧率一致；RTX/FEC 以抓包与计数器验证 |
| 连接正确性 | 首帧、静止画面、10 次以上刷新、重复弱网恢复、并发加入退出、单路失败不影响其他观看者 |
| 输入正确性 | DOWN 后断网/刷新/交权均释放；非控制者输入不注入；背压不重放过期动作 |
| 生产接入 | 控制平面确认设备租约、账号/角色、票据签发吊销；WSS、网关限流、配额及秘密管理 |
| 运行可靠性 | 24–72h 长稳，内存/FD/线程/硬件编码器回到基线；异常重启与灰度回滚 |

## 原生媒体核心的下一步

当前仍是 MediaCodec 先编码，再通过 kNative VideoFrame 和 passthrough 编码器接入 libwebrtc。
下游 VideoStreamEncoder 的编码前丢帧可能丢掉已编码参考帧。架构重构没有消除这个语义冲突。

应固定真实 libwebrtc 源码，利用现有 drop trace 对照 Source/Encode/RTP/Decode 数据确认每个丢帧原因。
推荐的后续实现是让 WebRTC 的帧调度先作用于原始输入，再异步提交 MediaCodec；另一选择是维护
专用的预编码适配及依赖恢复。两者都必须保留拥塞控制、pacer、RTX、RTCP 和有界时延。
不能通过宣称 rate controller 可信、全局关闭丢帧、无界缓存或降低所有 PLI 频率来代替正确性修复。

尚未完成：真实 pacer 队列与 oldest-packet 指标接入、自适应设备资源模型、硬件能力和 SPS 约束、
多档编码/SFU、生产监控上报与调度准入、业务角色/租约集成、零观看者采集节能。
这些事项必须按目标业务继续实施，不能从当前代码推导出可支持的实例数或延迟承诺。

## 基准与验收矩阵

| 场景 | 条件与检查 |
|---|---|
| 良好网络 | RTT 20–40ms，充足带宽，持续运动素材；记录首帧、呈现帧率、帧间隔 P95/P99、输入响应 |
| 带宽阶跃 | 8→1→0.4→8Mbps，分别记录配置码率、实际编码字节、wire rate、档位与恢复耗时 |
| 丢包 | 1/3/5/10% 随机丢包，100–500ms 突发丢包；记录 RTX/FEC、PLI、冻结与 IDR 大小 |
| 抖动与路由 | 10–80ms 抖动，单向黑洞，Wi-Fi/移动网切换，TURN UDP/TCP/TLS 路径 |
| 信令单断 | 视频继续播放，恢复不创建多余 native peer；过期才回收 |
| 多人混合网络 | 1/2/5/10 观看者；两种预算策略分别验证，控制者和观看者质量分别报告 |
| 宿主机容量 | 逐级增加云机实例；同时采集 VPU/GPU/CPU、温控、内存带宽、网络、P99 延迟 |
| 生命周期 | 至少数百次加入/退出、半开 socket 替换、刷新、并发控制权交接和进程停止 |

建议初始 SLO（必须先标定，非本次承诺）：良好同地域条件首帧 P95≤1.5s；720p60 玻璃到玻璃 P95≤150ms；
路径重新可用后 P95≤2s 恢复可解码画面。首次画面、音视频同步、冻结率和容量需分别测量。
端到端使用画面标记/高速摄像/输入响应实验，不将若干平均缓冲值相加作为实测。
